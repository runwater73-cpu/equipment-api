# Curios 兼容与装备损坏：0.2.0-alpha.2

适用 Minecraft 1.21.1、NeoForge 21.1.244 或更新的兼容版本、Java 21。神秘遗物联测使用 NeoForge 21.1.249。实际验证的 Curios 版本为 `9.5.1+1.21.1`，当前依赖范围限制在 9.5.x。Curios 是可选依赖，需另外安装，没有打包进本 API。

## 玩家看到的行为

同时安装两个模组后，人形护甲 `ArmorItem` 自动获得装备模板，包含本模板的格子空间与中心占位。头盔、胸甲、护腿、靴子的空预设部件槽被 Curios 槽取代，不会同时堆叠两套预设槽位。动物护甲不自动接管；武器、工具仍使用自己的装备模板。内容作者自己的独立槽位保留。

拿着护甲打开本 API 的装配界面，将对应饰品放入槽位，再选择格子位置。每个槽位只装一个物品单位。界面显示原饰品图标，空槽使用 Curios 提供的图标和名称，并区分功能槽与外观槽。装配与三维编辑仍由服务端验证。

已接管的槽位只在 Curios 原装配界面中隐藏，对外的 `isVisible()`、`getVisibleSlots()` 和物品适配查询仍保留原生含义。Curios 右键快捷装备被禁用，原生自动插入返回原物品；饰品的其他右键功能不被取消。已有饰品通过原生 API 更新耐久/数据、消耗或转换成另一件物品仍受支持。不要使用原生 `setStackInSlot` 向已接管的空槽安装物品；玩家的新安装及更换操作应走本 API 的装配事务。

侧栏和玩家绑定页接入原生槽位扩展的显示物品、空槽提示及创造模式中键复制。悬停可看到原物品说明、外观槽标记、原生禁用状态。支持显示开关的功能槽可用 **Alt + 右键**切换 Curios 原生渲染标记，仍按玩家的槽位类型和序号保存；它与装备部件自身的三维姿态可见性分别生效。9.5.1 原生外观槽的渲染优先级保持不变。

普通饰品真正保存在护甲内。穿戴对应护甲后，原生 Curios API 查询到它；脱下后效果停止，饰品随护甲移动。明确注册的永久绑定饰品是例外，首次生效时转为玩家持有，详见下文。没有另造属性计算、效果 Tick 或装备回调系统。

玩家绑定页签显示为“永恒之契”，面板标题为“「永恒之契，诸界不可断」”，使用作者提供的誓约文案。文字自动换行，槽位及点击区域一起下移；每页最多 32 个位置，按文案剩余高度减少可见行数，超出部分翻页。

单独使用本 API 时，原来的模板与槽位规则保持可用。

部件详情显示 Curios 的翻译槽名、当前拆卸条件和原物品说明，保留饰品作者的颜色与 Shift 展开提示。属性详情在装备原有数值下，按饰品分别列出原生属性修正，查询使用实际安装的类型与序号，并沿用 NeoForge/Curios 属性提示钩子。这些修正按当前玩家条件读取，不合并成虚假的装备总属性，也不会由界面再次施加；事件触发的特殊能力仍通过原说明展示。原模组未提供中文翻译的内容需要其语言文件或资源包补充。

## 槽位来源、数量与默认分配

读取 Curios 为该玩家实际注册的槽位，包括其他模组新增的类型。原始字符串 ID、验证器、标签、数量及动态数量修饰仍归 Curios 管理。一个类型只归属一种护甲位置，不在四件护甲上各复制一份容量。

| 原生 Curios 类型 | 默认所属位置 |
| --- | --- |
| `head`、`face`、`eyes`、`ear`、`ears` | 头部 |
| `belt`、`legs` | 腿部 |
| `feet`、`shoes`、`anklet` | 脚部 |
| `ring`、`hands`、`bracelet`、`necklace`、`amulet`、`charm`、`body`、`back` | 胸部 |
| 其他类型，包括第三方未知类型 | 胸部 |

例如手饰从 1 个增加到 5 个，5 个安装点全部出现在它配置的同一种模板上；不会按数量分流到头盔或靴子。空间不足时拒绝安装，由作者调整模板空间或部件形状。`template` 可以进一步限制到作者自己的模板，但装备仍须穿戴在 `armor_slot` 指定的人形护甲位置。槽位归属不决定模型所在的身体部位。

所有类型的默认占位为一个可旋转格子，方便直接接入。作者再按自己的饰品设计覆盖形状；没有对第三方饰品强加多格造型。原生外观槽存在且配置允许时，生成对应外观安装点；外观饰品只影响显示，效果仍由原生功能槽承担。

槽位增长会追加安装点，缩减后的空安装点会移除。超出容量的功能饰品交给原生 Curios 返还流程；外观饰品补充返还处理。已有物品不会因模板重算而直接被删掉，仍有内容的停用槽保留以便取回，不能继续安装。

本界面最多支持 256 个安装点，每个原生类型最多映射 128 个位置（功能/外观共用总上限）。不要用夸大的槽位数量模拟仓库。

## 数据包配置

文件路径：

`data/<你的命名空间>/equipment_structure_api/curios_compat/<文件名>.json`

例如 `data/myaddon/equipment_structure_api/curios_compat/default.json`：

```json
{
  "enabled": true,
  "slots": {
    "head": {
      "armor_slot": "head",
      "footprint": {
        "shape": [{"x": 0, "y": 0}, {"x": 1, "y": 0}],
        "rotations": [0, 1, 2, 3]
      },
      "enabled": true,
      "cosmetics": true
    },
    "myaddon_focus": {
      "armor_slot": "chest",
      "footprint": {
        "shape": [{"x": 0, "y": 0}],
        "rotations": [0]
      },
      "template": "myaddon:mage_chestplate"
    }
  },
  "items": {
    "myaddon:large_crown": {
      "shape": [{"x": 0, "y": 0}, {"x": 1, "y": 0}, {"x": 1, "y": 1}],
      "rotations": [0, 1, 2, 3]
    }
  },
  "excluded_equipment": ["myaddon:sealed_helmet"]
}
```

- `slots` 的键必须使用 Curios 注册的原始类型名，例如 `ring`，不是本 API 内部生成的十六进制 ID。此文件不负责新建 Curios 类型；新类型仍用 Curios 自己的注册方式。
- `armor_slot` 为 `head`、`chest`、`legs` 或 `feet`。
- `footprint.shape` 写实际占用格子，支持孔洞和不规则形状；沿用本 API 的局部归一化坐标与旋转规则。
- `items` 按单个物品 ID 覆盖类型默认形状，优先级更高。改动单物品覆盖后，已有饰品需要取出重装以采用新的包装定义。
- `template` 可选，要求装备实际使用指定模板；该模板仍需按本 API 原有流程定义和绑定。不会因为写了这个字段就创建模板。
- `slots` 中的 `"*"` 可覆盖未单独配置类型的默认分配与形状。
- 类型 `enabled: false` 退出该类型的存储和界面接管；全局 `enabled: false` 禁用整个兼容层。全局启用时，Curios 自带的右键快捷安装仍统一关闭。修改启用状态不会把护甲内物品自动复制到玩家槽位。
- 原生 `use_native_gui: false` 的类型可能是其他模组私有库存，默认不自动接管。作者可显式配置该类型（或通配规则）纳入装备装配。普通可见的自定义类型仍自动接入，排列沿用 Curios `order`，同序号按类型名稳定排序。
- Java 注册提供默认值，数据包配置覆盖默认值。同一路径按资源包叠放顺序读取；不同文件按资源路径排序，后面的键覆盖前面的键。建议整合包直接覆盖同名文件。
- 错误配置会记录日志并保留上一份完整配置。单次配置最多 256 个类型规则、1024 个单物品覆盖；生成的部件定义还受全局 4096 上限约束，单物品覆盖会按原生类型生成定义，不能无上限使用。

## Java 注册

在 common setup 的 `enqueueWork` 中注册，服务器加载世界/数据包前完成：

```java
CuriosCompatibility.registerSlot("myaddon_focus",
    new CuriosSlotProfile(EquipmentSlot.CHEST,
        GridFootprint.freelyRotating(GridShape.mask("##", ".#"))));

CuriosCompatibility.registerItemFootprint(
    ResourceLocation.fromNamespaceAndPath("myaddon", "large_crown"),
    GridFootprint.fixed(GridShape.mask("###", ".#.")));

CuriosCompatibility.excludeEquipment(
    ResourceLocation.fromNamespaceAndPath("myaddon", "sealed_helmet"));
```

这些配置类型本身不依赖 Curios 类，Curios 未安装时可以安全注册但不会生效。安装了 Curios 后，适配器才被启用。

有明确模板限制时使用完整构造器：

```java
new CuriosSlotProfile(EquipmentSlot.CHEST, footprint, true, true,
    Optional.of(ResourceLocation.fromNamespaceAndPath("myaddon", "mage_chestplate")));
```

程序主动准备一件护甲时，可在服务端调用 `CuriosEquipmentTemplates.prepare(armor, player)`。这属于可选兼容模块，直接引用前须确认 `ModList.get().isLoaded("curios")`。打开界面与穿戴查询已经自动调用，无需每 Tick 额外调用。

同一个饰品仍可用原有 `EquipmentComponentItemAdapters` 注册为武器或工具上的普通部件。解释方式由目标槽位决定；只有安装到 Curios 槽后才作为玩家饰品参与原生 Curios 效果。

## 三维编辑与自定义渲染

有佩戴渲染器时，默认位置是饰品作者原有的佩戴位置。编辑器的位移 0、旋转 0、缩放 1 表示不添加调整；保存的是相对原渲染结果的偏移，而不是世界绝对坐标。重置即可恢复原模组效果。模型仍执行原本动画。

标准 `ICurioRenderer` 在原生 Curios 图层中照常执行，本 API 只在调用周围应用玩家保存的平移、旋转、缩放和可见性。不替换 `CuriosRendererRegistry` 的对象，避免破坏其他模组的 renderer 类型判断。默认原始姿态不增加变换矩阵计算。

预览使用独立、未加入世界且不 Tick 的客户端玩家，不借用真实玩家的装备栏。预览、物体选择、拖动和服务端保存共用原来的三维编辑器。

默认头部类型相对头骨骼编辑，其他类型相对身体。模型需要其他基准时，在客户端 setup 注册：

```java
CuriosRenderFrames.registerSlot("myaddon_anklet", CuriosRenderFrames.Bone.LEFT_LEG);
CuriosRenderFrames.registerItem(
    ResourceLocation.fromNamespaceAndPath("myaddon", "right_glove"),
    CuriosRenderFrames.Bone.RIGHT_ARM);
```

单物品基准优先于类型基准。还可以实现 `CuriosRenderFrames.Frame` 自定义基准。变换单位与本 API 编辑器相同：16 单位为 1 格方块，Y 向上，Z 向前。

没有注册 `ICurioRenderer`、也没有独立图层适配器的装备饰品，复用 Minecraft 的原物品模型显示，图标类物品呈现为有厚度的物品外观。默认按装备槽位顺序排布在护甲表面，支持选择、平移、旋转、缩放及隐藏；编辑器和实际穿戴使用同一渲染入口，Curios 原生显示开关仍有效。布局随结构缓存，不在每帧解析物品资源。头部随头骨骼，胸部随身体，腿脚默认随左腿；作者可用上述基准接口调整。没有借此创造原作者未制作的专属佩戴模型。

第一人称手部图层、直接绕过 Curios 图层的特效，以及一件饰品同时依附多个肢体的特殊模型，需要作者使用 `CuriosRenderBridge.apply` 或自己的图层适配。默认调整把整个饰品模型作为一体移动，不承诺将任意多肢体模型自动拆分。

神秘遗物+ 1.21.1-1.1.1 的壮丽鞘翅和混沌鞘翅使用独立 `EnigmaticElytraLayer`。本适配调用该原始图层完成预览，并在世界图层外应用同一偏移；模型、纹理与动画仍由原模组提供。其他独立图层可以通过 `CuriosLayerPreviewRegistry.register` 注册预览工厂，并在其世界图层接入 `CuriosRenderBridge.apply`。注册适配器也会关闭对应物品的默认物品模型，避免双重显示。

## 永久绑定饰品归属于玩家

七咒之戒和救赎之戒默认注册为玩家绑定例外。空手即可打开本 API 装配界面，切换“永恒之契”页；不需要先获得护甲。该页按原生类型和实际容量展示多个槽位，每页最多 32 个，超出时翻页或滚轮翻页。只接受明确声明为玩家绑定的饰品，Shift 点击背包中的此类饰品也会直接绑定到玩家。数量、原生重复物品限制、互斥限制及前置条件仍有效；声明两个绑定饰品不代表能绕过它们自己的互斥规则。

首次安装直接写入玩家的 Curios 原生存储；已有待装配绑定部件则在首次穿戴并验证通过时从护甲转移到玩家。两处不会各保存一份。此后脱甲、换甲、装备损坏均不解除绑定，也不会把绑定交给取得旧装备的另一名玩家。

“永恒之契”只展示实际归玩家持有的绑定物品，以及适合声明绑定物品的空闲基础/永久解锁位置。已被护甲中的普通饰品占用的位置不会显示在该页。临时新增槽位仍按类型进入对应装备模板；绑定饰品提供的扩容也遵循相同归属，不因来源是绑定物品就变成绑定页独有容量。此页和装备共用 Curios 数量与索引，不能重复安装。

绑定物品占用玩家原来的同一个 Curios 槽位索引，其查询、Tick、属性、死亡规则和克隆仍由 Curios 执行。装配界面的对应槽以金色边框显示，并提示“已绑定玩家”。它不占装备格子空间，也不允许把普通饰品安装到同一个已保留的索引。其他装备已经存有该索引的饰品时，该饰品仍保留在装备中，可以取出换到其他空槽，不能额外叠加容量。

绑定后的拆卸仍检查原模组的 `canUnequip` 和事件。七咒之戒在生存模式不能卸下；原模组允许的创造模式拆卸可从本界面完成。原模组主动销毁、解咒或替换原生物品仍具有权限。未生效的待装配绑定饰品可以取回。**不会把任意 `canUnequip=false` 都识别成永久绑定**，例如条件性锁定仍属于普通装备内饰品。

作者可以注册自己的绑定类型：

```java
CuriosCompatibility.registerPlayerBoundItem(ResourceLocation.parse("myaddon:soul_ring"), true);
```

数据包同目录支持 `"player_bound_items": {"myaddon:soul_ring": true}`，单物品值 `false` 可覆盖默认策略。已经生效的绑定不会因撤销注册而静默丢失，仍由原生存储和原拆卸规则处理。当前玩家绑定物品不作为装备部件参与装备三维编辑。

永久绑定只允许使用原生基础容量与永久数量修饰提供的槽位；由装备或饰品临时增加的槽位仍供普通饰品使用，不接受新的永久绑定。这防止脱下提供容量的护甲变成七咒的卸下手段。没有凭空新增另一套绑定容量。管理员删除槽位类型或撤销永久数量修饰属于主动修改规则，仍按 Curios 原生溢出恢复处理，并非不可改变的玩家特权。

神秘遗物开启 `autoEquip` 时，保留原库存 Tick 的佩戴行为；`ultraHardcore` 起始赠予仍可直接绑定，无须护甲。适配检查真实安装结果后才向原模组报告成功，普通饰品的强制装备入口保持关闭。佩戴时间直接使用原模组的计时附件与 Tick，不重置、不另起计时器。其他模组如有特殊的强制绑定流程，需要通过 `PlayerBoundCurios.install` 接入；此方法仅执行单件安装，调用方负责成功后扣除来源物品，失败时必须保留来源。

## 动态增槽与跨装备

容量只由 Curios 原来的数量修饰器算一次。本 API 读取结果来生成安装点，不按每件护甲重新累加。比如胸甲上的护符增加 `charm`，而配置将 `charm` 映射到头部，增加的位置全部出现在头盔模板；没有头盔时仍有原生容量，但普通饰品必须装入并穿戴对应装备才生效。

多个来源的叠加、相同修饰器 ID 的规则、自增同类型槽位、条件解锁沿用原模组和 Curios。取下或损坏来源装备后，Curios 移除其修饰器；目标装备超出容量的生效饰品交给原生溢出返还流程，不能保留额外效果或复制物品。未穿戴装备中的停用部件保留为可取回内容，不能在停用位置继续安装。

当前装配输入是手持/背包装备，打开时不把它视作穿戴。装备自身提供的临时槽位只在实际穿戴生效期间存在；本版本没有伪造“预先穿戴”去激活额外容量。互相依赖或自己维持容量的饰品依赖关系保留原模组的处理方式，不承诺修复第三方本身的循环配置。

## 保存、死亡与护甲损坏

普通饰品只由护甲保存，永久绑定饰品只由玩家的 Curios 原生存储保存。原生 Curios 客户端同步仍包含实时物品，但玩家持久化数据会排除护甲已拥有的副本。直接修改原饰品 `ItemStack` 的数据会写回护甲；复制护甲前也会刷新。原生重载的“清空再构建”被隔离为运行时重建，不会清空护甲。

`saveInventory(true)` / `loadInventory` 的明确备份转移路径受支持：清空时先解除装备归属，恢复时优先回到对应装备；缺少护甲、槽位或空间时返还背包/掉落。重复恢复与现有物品完全相同的快照不会复制同一个拥有者。第三方若同时备份护甲和饰品，需要自行定义恢复范围，不能把两个备份都当作额外新物品。原生 setter 转换普通饰品时重新检查新物品的格子形状；不能容纳时仅返还转换后的物品，不返还已被消耗的旧物品。

装配尚未穿戴的护甲不会触发实际佩戴效果；真正穿戴、停用、重新启用、脱下仍由 Curios 触发 `onEquip`、`onUnequip`、`curioTick` 和属性更新。玩家绑定页安装后调用原生 `onEquipFromUse`，原生 Tick 继续负责实际佩戴回调。预览使用独立且不 Tick 的玩家，复制原生容量和渲染状态，避免用预览触发游戏效果。

默认死亡掉落让饰品留在护甲里面，不再额外生成一个散落饰品。Curios 的显式 `ALWAYS_KEEP`、`ALWAYS_DROP`、`DESTROY` 和保留设置继续生效；需要独立保留的饰品先从护甲分离，走 Curios 原有克隆路径，再返还新玩家以从界面重装。整合包使用墓碑、灵魂绑定或其他接管掉落的模组时，应额外做实际联测。

耐久耗尽由核心的 `EquipmentBreakRecovery` 统一处理，Curios 不在场也有效：

1. 读取完整部件清单，先验证所有要返还的部件都能无损还原成物品。
2. 验证成功后清除宿主对部件的拥有关系，返还到玩家背包；背包满则沿用 Minecraft 的物品掉落行为。其他生物在自身位置掉落。
3. 再执行原本的装备损坏与破坏回调。手动拆卸限制不阻止这一流程。
4. 缺少还原工厂、工厂丢失数据、没有可用接收实体或事件取消时，保留宿主与所有部件并将宿主保持在 1 点耐久，防止部分返还/部分丢失。

作者通过 NeoForge 事件覆盖单个部件的损坏策略：

```java
@SubscribeEvent
public static void onBreak(EquipmentBreakEvent event) {
    if (!event.structure().hostId().equals(MY_TEMPLATE)) return;
    event.setAction(MY_COMPONENT_SLOT, EquipmentBreakEvent.Action.DESTROY);
    // 默认是 RETURN。event.setCanceled(true) 会阻止本次物理损坏并保留全部部件。
}
```

只对事件中实际装有部件的槽调用 `setAction`。本机制针对 `hurtAndBreak` 的耐久耗尽；物品实体被岩浆/虚空销毁、命令清除、其他模组直接替换 `ItemStack` 属于其他生命周期，不会一概返还部件。

## 验证范围与源码依据

验收以原生槽位契约为单位，神秘遗物只是其中一套真实内容测试：

| 原生机制 | 本版结果 |
| --- | --- |
| 类型、序号、数量修饰器、跨装备增槽 | 由 Curios 计算；本 API 将结果映射到固定护甲类别，超限回收遵循原生流程 |
| 标签/验证器、canEquip/canUnequip 及事件 | 沿用原生校验；适配查询保持原意；只在实际写入入口限制手动安装方式 |
| onEquip/onUnequip/curioTick、属性 | 原生驱动，验收检查次数与停用/恢复行为；外观槽不获得功能效果 |
| 原生渲染开关、外观优先级、客户端同步 | 标准渲染链实机验证；三维编辑为原模型追加偏移 |
| 槽位扩展接口 | 接入显示物品、空槽提示、创造复制；创造复制有服务端权限检查 |
| 保存、明确备份转移、转换、消耗、死亡 | 保持单一存储归属；测试分别覆盖这些路径 |
| 私有隐藏类型、强制空槽写入、自建渲染层 | 不假定通用语义，需显式配置或专项适配 |
| 永久绑定识别 | 作者或整合包声明；不能仅根据一次 canUnequip=false 判断永久绑定 |

每类最多映射 128 个原生序号，每件装备最多 256 个安装点；功能和外观安装点都计入上限。超出该映射范围不属于本版的完整兼容承诺。原生存储类型被模组整体替换、槽位类型热删除及第三方同时恢复多种备份的流程，需要专项联测。

服务端测试覆盖自定义类型、单物品形状优先级、原生验证器、护甲归属、复制前写回、原生重建、死亡三种显式规则、外观槽缩减、同 Tick 查询缓存、右键禁用与核心损坏恢复。独立客户端与服务端测试覆盖实际格子安装、原生模型预览、三维坐标保存、穿戴同步及世界渲染。测试部件不会进入发布 JAR。

这是一版 alpha，不宣称已经联测所有饰品模组。使用原生 tick/attributes/render layer 可减少重复实现，但第三方绕过这些公开入口的特殊逻辑仍需专项适配。

研究依据为 [Curios 1.21.1 源码](https://github.com/TheIllusiveC4/Curios/tree/6b122c8a7e2b514fd94197459ade11f19a0bfb09)，重点查看 `CuriosEventHandler`、`CurioInventory`、`DynamicStackHandler` 与 `CuriosLayer`。运行时依赖原模组，不复制其资源或重新实现其效果引擎。
