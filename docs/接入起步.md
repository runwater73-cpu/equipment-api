# 0.1.1 接入起步

适用 Minecraft 1.21.1、NeoForge 21.1.244、Java 21。先建一个独立 NeoForge 内容模组工程，将发布的 `equipment_structure_api-0.1.1.jar` 放进工程的 `libs` 目录。

## 添加依赖

在内容模组 `build.gradle` 的 `dependencies` 中添加：

```groovy
implementation files('libs/equipment_structure_api-0.1.1.jar')
```

在内容模组 `src/main/templates/META-INF/neoforge.mods.toml` 添加依赖，将 `yourmod` 改成实际模组 ID：

```toml
[[dependencies.yourmod]]
modId="equipment_structure_api"
type="required"
versionRange="[0.1.1,0.2.0)"
ordering="AFTER"
side="BOTH"
```

开发运行时由 Gradle 加载依赖 JAR，不要再往开发实例 `mods` 中放第二份 API。发行给玩家时，需要同时安装内容模组和 API。

## 直接使用预设剑模板

在公共初始化 `FMLCommonSetupEvent` 的 `event.enqueueWork(...)` 中绑定物品。注册代码必须在客户端和服务端都执行：

```java
EquipmentHostProviders.register(Items.IRON_SWORD, BuiltinEquipmentTemplates.SWORD);
```

模板 ID 是 `equipment_structure_api:sword`。它包含既定的刃饰、裹柄、护手、魂饰、挂饰五个安装位，以及 9×9 面板和剑形本体占位。五个安装位与 81 个面板格子是不同概念；中心本体会占用其中部分格子。

API 本身不自动绑定所有原版装备。内容作者可以把自己的剑、另一个模组的剑或 Item Tag 绑定到相同模板，也可以新建完全独立的类型和模板。部件没有模板。

运行游戏并手持铁剑，使用按键设置中的装配快捷键，或输入 `/equipment_structure_api open`。打开流程会在服务端初始化装备。此时应显示网格面板和右侧安装位图标。

## 注册一个用于验证的部件

下面这段代码也放在公共初始化中。它把普通紫水晶碎片适配成剑的刃饰，方便在自己的演示工程中先验证安装流程。该示例只接受能够按下面工厂完整还原的普通物品；带有额外 Data Components 的物品需要自行保存和还原数据。

```java
ResourceLocation partId = ResourceLocation.fromNamespaceAndPath("yourmod", "test_blade");
EquipmentComponentRegistry.register(
    EquipmentComponentDefinition.builder(
        partId, BuiltinEquipmentSlots.BLADE, BuiltinEquipmentSlots.BLADE)
        .suitableFor(BuiltinEquipmentTypes.SWORD)
        .footprint(GridFootprint.freelyRotating(GridShape.mask("##", ".#")))
        .itemFactory(instance -> new ItemStack(Items.AMETHYST_SHARD))
        .build());

EquipmentComponentItemAdapters.register(
    partId, Items.AMETHYST_SHARD, partId,
    stack -> Optional.of(new CompoundTag()));
```

上述 API 类在 `dev.equipmentstructure.api` 和 `dev.equipmentstructure.api.grid` 包中；其余类为 Minecraft `ResourceLocation`、`ItemStack`、`Items`、`CompoundTag` 和 Java `Optional`。

左侧装备输入位在空着时也显示边框，可以直接放回装备。右侧槽位按数量增减行数，每行 4 个、最多显示 6 行；超过 24 个时用滚轮浏览。

把紫水晶碎片拿到鼠标上，点击右侧刃饰安装位。部件应出现在面板里，占三个格子。拖动已安装部件可调整位置，R 旋转；点击安装位取下，Shift 点击快捷取出。槽位类型不匹配、空间碰撞或越界时，服务端会拒绝操作。属性与行为需要另行注册，这个最小验证部件不附带属性。

自有物品可实现 `EquipmentComponentItem#createComponent(ItemStack)`，外部物品可用 `EquipmentComponentItemAdapters` 的单物品或 Tag 适配。无论入口是哪一种，都必须先注册部件定义并提供可靠的反向物品工厂。

## 自定义模板与批量绑定

复制仓库 `src/main/resources/data/equipment_structure_api/equipment_structure_api/host_definition/sword.json` 到内容模组：

```text
src/main/resources/data/yourmod/equipment_structure_api/host_definition/my_sword.json
```

把 `id` 改为 `yourmod:my_sword`。保留剑类型可以继续接受声明支持剑的部件；也可以将 `equipment_type` 改为自己的类别 ID，并让自己的部件显式支持该类型。修改 `slots` 定义安装位，修改 `grid` 定义面板与本体占格。

正式模板由数据注册表加载。修改模板后重新启动测试世界或服务器，确保注册表重新加载；不要把 `/reload` 当作替换全部动态注册表的保证。物品已有结构时不会被初始化操作覆盖，验证新模板使用一把新剑。

绑定有四类入口：固定 Item 绑定、按 ItemStack 判断的 Provider、Item Tag 批量绑定、NeoForge `host_binding` Data Map。它们都引用已存在的模板 ID。

Data Map 文件位置：

```text
src/main/resources/data/equipment_structure_api/data_maps/item/host_binding.json
```

```json
{
  "values": {
    "minecraft:iron_sword": { "host": "yourmod:my_sword" }
  }
}
```

Java Builder 只构造模板对象，不会向数据注册表注册新条目。纯 Java 运行时结构使用 `createStructure()`，如需网格还必须显式调用 `EquipmentGridRegistry.registerHost(hostId, board)`。正式可共享模板建议通过 JSON 提供。

## 开发验收

至少验证首次打开面板、正确类型安装、错误类型拒绝、格子碰撞、旋转、拆卸、Shift 快捷取出、退出重进后的保存，以及客户端与独立服务器联机。

本仓库测试夹具与正常 API 构建分离。`src/clientTest` 用于自动验收，不是发布的 Demo 模组；自己的演示内容放在独立工程中。
